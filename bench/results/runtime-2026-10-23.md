# Runtime checks, 23 October 2026

These measurements compare commit `1fa7ef4` with this revision on an Apple
M2 Max, macOS/Darwin 25.3.0, Node 25.2.1, arm64. The runtime fixtures use
JSDOM. Each comparison warms both implementations and alternates their
order between samples. No test suite or build ran alongside the measurements.

| Workload | Before, median | After, median |
| --- | ---: | ---: |
| Register 5,000 effects for one owner | 165.925 ms | 2.001 ms |
| Re-register those 5,000 owner/ID pairs | 149.233 ms | 1.541 ms |
| Dispose those 5,000 effects | 0.384 ms | 1.298 ms |
| 200 unrelated state updates with a 5,000-item derived projection | 12.211 ms | 0.420 ms |
| Compile a 10,558-byte directive fixture | 4.605 ms | 4.489 ms |

The effect and derived workloads use nine samples. Compilation uses 15
samples after 30 warmups. The derived fixture performs 50 warmup updates per
instance, then measures microtask updates without timers or browser paint.
The [raw samples](runtime-2026-10-23.json) include the correctness counts.

Effect registration now looks up an owner/ID pair in an index instead of
scanning every effect. Re-registration was about 97 times faster in this
fixture. Disposal takes about 0.9 ms more for 5,000 records because it also
removes index entries and safely handles callbacks that register or dispose
other effects. Both versions leave zero owned records after disposal.

The derived fixture changes a displayed counter while a separate array stays
unchanged. Before, each update created another 5,000-item projected array.
After, all nine samples reused the original projection: zero replacements,
down from 200. Source changes, nested writes and forced updates have separate
regression tests. Unknown callbacks and explicit side effects keep the eager
path.

The compiler fixture emits byte-identical JavaScript in both versions. Its
timings are close enough that this check does not establish a compiler
throughput improvement.

These are isolated workloads. Timing varies with machine load, while the
array-replacement and effect-record counts are deterministic. The results
do not measure whole-app speed, layout, paint or network work. The existing
framework comparison charts retain their separate 14 October measurements.

## Reproduce

Build the baseline in a separate checkout, then build this revision:

```bash
git worktree add --detach /tmp/htms-baseline 1fa7ef4
npm --prefix /tmp/htms-baseline ci
npm --prefix /tmp/htms-baseline run build
npm run build
node bench/compiler.mjs /tmp/htms-baseline/dist --runs 15 --warmup 30
node bench/derived.mjs /tmp/htms-baseline/dist --runs 9 --updates 200
node bench/effects.mjs /tmp/htms-baseline/dist --count 5000 --runs 9
```

Run those commands sequentially with other build and test jobs stopped.
Each script prints individual samples and medians; the derived fixture also
asserts its rendered output and array-replacement counts.
